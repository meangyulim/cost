# 게시 검증과 중복 발송 방지

이 문서는 실행 계약입니다. 메시지 발송 기능은 이 저장소에 구현되거나 연결되어 있지 않습니다.
현재 단계는 TEST 사이트 구축이며 실제 브리핑·카카오톡 전송을 실행하지 않습니다.

매 실행에서 실제 시작 시각을 시계로 확인해 KST/UTC로 기록하고, 원격 최신 소스·manifest·회차·dispatch를 읽습니다.
한국 회차 날짜는 한국 시장 날짜, 미국 회차 날짜는 뉴욕 시장 날짜입니다.
거래일과 휴장·조기 폐장은 공식 달력으로 확인합니다. 휴장일에는 게시와 전송을 모두 생략합니다.

새 회차만 추가하며 같은 회차를 덮어쓰지 않습니다. 이미 존재하면 내용·배포·발송 상태만 확인합니다.
전체 사이트를 배포하여 이전 글을 유지합니다. 같은 커밋에 대한 Actions Pages 배포 성공을 확인합니다.
정확한 회차 공개 URL을 인증·쿠키 없는 HTTP GET과 비로그인 브라우저로 각각 확인합니다.
HTTP 200, 로그인 이동 없음, 회차 경로, 한글·실제 주가·숫자·날짜 포함 KST·원문 출처를 확인합니다.
둘 중 하나라도 실패하거나 검사 도구가 없으면 메시지를 보내지 않습니다.

## 원격 attempted 기록을 먼저 확보

회차별 `dispatch/<회차 ID>.json` 파일에 최소 비민감 상태만 저장합니다.
예시는 형식 설명이며 실제 attempted 기록을 생성하지 않습니다.

```json
{
  "report_id": "kr-close-YYYY-MM-DD",
  "status": "attempted",
  "attempted_at_kst": "날짜와 +09:00을 포함한 실제 시각",
  "attempted_at_utc": "날짜와 +00:00을 포함한 실제 시각",
  "url": "GitHub가 반환한 실제 Pages 원점과 정확한 회차 경로",
  "commit": "배포 검증한 보고서 커밋",
  "verification": {"deployment": "passed", "anonymous_http": "passed", "browser": "passed"}
}
```

전송 직전에 원격에서 해당 파일 부재를 확인하고 새 파일을 커밋해 일반 fast-forward push합니다.
여러 실행이 동시에 쓰면 첫 번째 push만 성공하도록 일반 Git 충돌 검사를 유지합니다.
충돌 시 force push·자동 덮어쓰기·발송 재시도를 하지 않습니다. API 조건부 생성도 실제 도구가 지원할 때만 사용합니다.
원격에서 해당 attempted 기록과 자신이 쓴 커밋을 다시 읽어 저장 성공을 확인하기 전에는 보내지 않습니다.
이미 attempted/sent/실패/불명확 상태가 있거나 저장 결과를 확정할 수 없으면 보내지 않습니다.

기록 저장 후 발송 권한이 확인된 PlayMCP 카카오톡 나챗방 도구로 핵심 요약과 정확한 회차 URL을
합쳐 200자 이하로 한 번만 전송합니다. URL 때문에 200자를 맞출 수 없으면 보내지 않고 제한을 보고합니다.
전송 실패·불명확 응답도 재시도하지 않습니다. 비민감 status는 sent/failed/unknown으로 갱신할 수 있으나
상태 갱신 실패는 재전송 이유가 아닙니다. 카카오톡 응답 속 개인정보나 대화는 저장소에 올리지 않습니다.
대화 읽기는 일반 요구사항으로 추가하지 않으며 실제 도구의 사전 조건을 따릅니다.

예약 결과에는 거래일과 달력 원문, 예정/실제 시작 시각, 클라우드 환경, Git 커밋,
배포 상태, 정확한 회차 URL, HTTP/브라우저 각각의 검사 결과, attempted 저장과 도구 응답 상태를 남깁니다.
실행하지 않은 검사, 관찰하지 못한 성공, 모델 지정 결과를 만들어 기록하지 않습니다.
