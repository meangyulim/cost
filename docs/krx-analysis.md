# KRX 일별 분석 입력

2026.10.01 사용자가 승인된 인증키와 6개 API를 제공했고 실제 2026.09.30 데이터 조회를 확인했다.
키 값은 저장소·보고서·실행 인수에 저장하지 않는다. `scripts/krx_analysis.py`는 환경변수
`KRX_API_KEY`를 읽고 공식 `https://data-dbg.krx.co.kr`의 AUTH_KEY 헤더로만 전달한다.
리다이렉트는 거절하고 TLS 검증을 유지한다. 원시 응답·오류 본문·헤더는 로그나 산출물에 남기지 않는다.

## 최초 연결

저장소 Settings → Secrets and variables → Actions → New repository secret에서
이름 `KRX_API_KEY`, 값은 발급된 인증키로 등록한다. 공개 Variables가 아니라 Secrets를 사용한다.
현재 연결된 GitHub 도구는 secrets API를 지원하지 않아 이 최초 등록은 계정 설정에서 해야 한다.
사용자가 준 키를 채팅 기록에서 복사해 공개 파일로 전달하는 방식은 사용하지 않는다.

Actions → `Collect KRX briefing inputs` → Run workflow로 기준일을 지정한다.
빈 기준일은 KST 어제이며 아직 제공되지 않은 날짜는 과거에 데이터가 있는 날짜로 이동한다.
실제 결과의 `data_date`를 확인한다. 요청일과 같다고 추정하지 않는다.
65거래일 이력, 최신일과 직전 5거래일 종목/ETF 자료를 수집한다. 외부 패키지와 별도 서버는 필요하지 않다.

반환된 실행의 성공과 artifact `krx-analysis-<run ID>`의 `analysis.json`을 확인한다.
공개 저장소의 Actions 산출물을 비밀 저장소로 취급하지 않는다. 산출물에는 비밀키나 원시 전체 종목 자료를 넣지 않는다.
보존 기간은 3일이며 별도 영구 데이터 아카이브를 생성하지 않는다.

## 사용자 요청에 연결

새 브리핑 요청에서 원격 최신 코드를 확인하고 아래 형식의 `data/krx-request.json`을 일반 fast-forward로 갱신하면
push 이벤트로 분석 작업이 실행된다. 비밀키는 요청 파일에 넣지 않는다. 반복 예약/cron은 추가하지 않는다.
이 파일만 바뀌어도 Pages 워크플로가 실행될 수 있으나 기존 보고서 내용은 바뀌지 않는다.

```json
{"end_date": "", "requested_at": "날짜 포함 실제 KST 시각"}
```

작업 성공과 해당 요청 커밋의 run ID, 기준일, 조회 시각, 산출물을 확인한 다음 브리핑 작성에 활용한다.
Actions Secrets는 Work 대화에 직접 전달되지 않으므로 대화 실행이 키를 읽는다고 가정하지 않는다.
산출물을 가져올 수 없거나 키 미설정/승인/네트워크 오류이면 분석 미확인을 표시하고 성공으로 취급하지 않는다.

장전·장중 브리핑에는 최신 제공 일별 자료를 전일/이전 거래일 배경 분석으로만 사용한다.
장후에는 해당 거래일 자료가 실제 반환됐는지 확인한다. 제공 전이면 이전 종가를 당일 종가로 표시하지 않는다.
기존 거래일 달력 검증·뉴스/공시 조사·관찰 종목 선정·게시·검증·카카오 1회 전송 절차는 계속 적용한다.
시장 폭/지수 강도는 `interpretation`과 계산 범위에 기준일을 붙여 반영할 수 있다. 과거 회차는 수정하지 않는다.

## 지표와 해석

| 지표 | 계산 | 해석 범위 |
|---|---|---|
| 추세 | 종가/20일/60일 평균과 20일선의 5거래일 변화 | 조건 충족 여부이며 미래 상승 확률 아님 |
| 시장 폭 | 거래량>0·유효 등락률 종목의 상승 비율 | 우선주 등 포함, 휴면/결측 제외 수 기록 |
| 거래대금 | 전체 제공 종목의 합계 / 직전 5거래일 평균 | 거래 활성도이며 순자금 유입 아님 |
| 지수 강도 | KRX 가격지수 20거래일 수익률 − 코스피 수익률 | 업종·테마 등 혼합; 샤프·변동성·평가지표 계열 제외 |
| ETF 강도 | 유동성 필터 통과 상품의 5거래일 가격수익률 | 배당/분할 보정 없음, 이름 기반 구조 필터의 한계 있음 |

이 6개 API에는 투자자별 순매수 정보가 없다. 외국인·기관 수급을 추정해 채우지 않는다.
`forecast_probability`는 null, `backtest_status`는 not_validated로 유지한다.
미래 예측을 추가하려면 과거 시점별 이용 가능 데이터로 walk-forward 검증하고 보정·비용·생존편향을 처리해야 한다.
현재 버전은 기술적 상태와 확인할 조건을 제공한다.

KRX 원시 전체 자료를 Pages/public/data/reports에 직접 저장하는 것은 코드에서 차단한다.
공개 보고서에 반영할 정보의 범위는 KRX 이용약관과 사용 허가를 확인한다.
출처는 한국거래소 통계정보로 표시한다. API별 정확한 자료 갱신 시각은 확인하지 못했다.

공식 근거: [서비스 목록](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd),
[이용약관](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO002.jsp),
[GitHub Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).
